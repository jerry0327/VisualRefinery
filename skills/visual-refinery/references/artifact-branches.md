# Artifact Branches

Read the branch that matches the requested output. These are patterns, not mandatory templates.

## Slide deck / presentation

Optimize for spoken delivery, scan speed, and one dominant message per slide.

A strong deck often follows a sequence such as:

1. context or question;
2. why it matters;
3. key evidence or mechanism;
4. comparison or decision point;
5. implications;
6. action, recommendation, or takeaways.

Use varied but coherent slide architectures:

- statement + evidence;
- image + interpretation;
- chart + conclusion;
- comparison columns;
- process or decision flow;
- timeline;
- single strong visual with annotation;
- compact table when exact comparison matters.

Avoid decks where every slide is title + bullets or a grid of interchangeable cards.

When the deck is editable, prefer native text, charts, tables, and shapes. Put secondary methodological detail in speaker notes when appropriate rather than crowding the slide.

For presentation QA, inspect both the full deck montage and every complete slide at readable size.

## Analytical report / client-facing PDF

Optimize for sustained reading, navigability, evidence traceability, and visual rhythm across pages.

Possible structure:

1. cover;
2. concise executive or editorial introduction;
3. decision summary;
4. evidence / context overview;
5. thematic sections;
6. detailed comparisons or profiles;
7. implications and scenarios;
8. recommendations or action checklist;
9. methods / limitations when necessary;
10. compact sources and credits.

Use tables, charts, callouts, photographs, diagrams, maps, and pull quotes only when they improve comprehension.

Do not turn every paragraph into a card. Reports need real prose and transitions.

Keep line length comfortable and use recurring page patterns without making every page identical.

## One-pager / executive brief

A one-pager is an exercise in prioritization.

Recommended hierarchy:

- one clear title or conclusion;
- a short context statement;
- 3–5 decision-driving points;
- one central visual, table, or comparison if useful;
- clear next step or recommendation;
- compact source / date note.

Do not shrink a multi-page report into unreadable type. Remove nonessential detail and link or append supporting material elsewhere.

## Poster

A poster should work from several viewing distances.

At a distance:
- title and primary finding are legible;
- section structure is obvious.

At conversational distance:
- key figures and conclusions are understandable quickly.

Up close:
- methods, citations, and details remain readable.

Use a clear visual path. Do not fill the entire canvas with equal-density text boxes.

For research posters, prioritize figures, methods clarity, and conclusion traceability over decorative branding.

## Guide / handbook / field reference

Optimize for retrieval rather than linear reading.

Useful patterns include:

- task-based sections;
- symptom / problem / scenario indexes;
- checklists;
- decision trees;
- quick-reference tables;
- warnings placed next to the affected action;
- cross-references and navigation aids.

Maintain consistent terminology and repeated structural cues so the reader can find information quickly.

## Educational / training artifact

Design around the learning objective.

Sequence from prerequisite concepts to application. Reduce extraneous cognitive load.

Use:

- worked examples;
- progressive diagrams;
- comparison cases;
- retrieval questions;
- short recap sections;
- misconception correction;
- decision or mechanism visuals.

Do not confuse visual novelty with teaching value.

## Data-led report or narrative dashboard

Start from the decision or monitoring question, not the available chart types.

For each metric, state:

- definition;
- denominator;
- time window;
- comparison basis;
- target or reference point if relevant;
- what action the metric informs.

Organize the page from status → drivers → segments → actions rather than displaying every available metric equally.

Use charts for patterns and tables for precise lookup.

## Technical architecture / system explainer

Make boundaries, dependencies, data flows, failure modes, and interfaces visible.

Prefer:

- layered architecture diagrams;
- sequence diagrams;
- request / data flow diagrams;
- interface tables;
- state transitions;
- deployment topology;
- risk or failure-mode callouts.

Avoid a single giant diagram that tries to encode every implementation detail.

## Visual comparison

When comparing options, define the dimensions before assigning visual emphasis.

Good dimensions may include:

- cost;
- performance;
- effort;
- risk;
- accessibility;
- quality;
- timing;
- maintainability;
- evidence confidence;
- user burden.

Make trade-offs explicit. Do not convert subjective judgments into fake precision simply to populate a scorecard.

## Revision of an existing artifact

Before editing:

1. inspect the entire existing artifact;
2. identify what already works;
3. separate local defects from global design problems;
4. preserve working content, ordering, and visual language unless redesign was requested;
5. correct the smallest coherent set of pages;
6. render and inspect the entire revised artifact for regressions.

Do not redesign a successful document merely because a different style is possible.
